# Методология Тестирования 

Виды тестирования:
* Модульное тестирования
* Интеграционное тестирования
* приёмочное тестирование
* Проверка целосности программы

Модуль - это любой Python файл.

## Пять принципов тестирования
1. Изолированность - каждый тест должен выполнятся изолированно

2. Воспроизводимость - при одинаковых входных данных, тест должен давать одинаковый результат.
3. Быстрота/скорость(Больше относится к модульному тестированию) - именно модульные тесты должны выполнятся доли секунды.
4. Читаемость - по тесту должно быть понятно что проверяется и какой должен быть результат.
5. Один тест - одна проверка. (незначительный прицип) 

## **Модульное тестирования(Unit testing)**
Модульное тестирования - проверка наименьших независимых частей программы(юнитов) в отрыве от остальной системы или алгоритма.

**Структура Unit теста: AAA**

1. Подготовка (arrange) - создание входных данных и настройка их окружения.
2. Действие (Act) - Вызов тестируемого кода.
3. Проверка (Accert) - сравнение результата с ожиданием.

Пример тестирование без фреймворка:
wo.py
```py
""" Модуль для получения суммы двух чисел """

def add(a,b):
    """Функция для посчёта суммы двух чисел

    Args:
        a (int/float): Первое слагаемое
        b (int/float): Второе слагаемое 

    Returns:
        int/float: Арифмитическое сумма двух чисел (a+b)
    """
    return a+b

def  divide(a,b):
    """Функция для подсчёта частного двух чисел.

    Args:
        a (int/float): первое слагаемое (Делимое)
        b (int/float): второе слагаемое (Делитель)

    Returns:
        int/float: Арифместическое частного двух чисел.
    """
    if b == 0:
        raise ValueError('Деление на ноль невозможно')
    return a/b
```

test.py
```py
from wo import add, divide

""" ------------- Проверка сложения --------"""
# A1: Подготовка входных данных
a, b = 2, 3
expected = 5
# A2: Вызов функции
result = add(a,b)
# A3: Проверка результатов
assert result == expected, f'Ожидание {expected}, Результат: {result}'
print("Тест 1 пройден")

""" ------------- Проверка деления --------"""
# A1: Подготовка входных данных
a, b = 10, 2
expected = 5
# A2: Вызов функции
result = divide(a,b)
# A3: Проверка результатов
assert result == expected, f'Ожидание {expected}, Результат: {result}'
print("Тест 2 пройден")

""" ------------- проверка исключения --------"""
# A1: Подготовка входных данных
a, b = 0, 10
# A2: Вызов функции
try:
    result = divide(a,b)
    assert False, 'Ожидали ValueError, но исключения не возникло'
except ValueError as error:
    assert str(error) == 'Деление на ноль невозможно'
# A3: Проверка результатов
print('Тест 3 пройден')
```

> `assert` - предположиение, которое проверяет условие и при провале проверки побуждает `AssertionError` с соответствующим сообщением.<br>В данном тесте при возникновении ситуации деления на ноль побуждается `ValueError` 

Ручные Unit тесты(базовые подходы) удобны только для проктых модулей и функций. 

Для сложных в плане архитектуры проектов, больших по объёму и содержанию, для тяжёлых классов предпочтительнее использовать аппаратные инструменты тестирования. эти инструменты позволяют  настраивать автоматический запуск, отчёт, удобную проверку исключений.
